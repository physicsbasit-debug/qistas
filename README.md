# قِسطاس

تطبيق عربي RTL خفيف واحترافي لتوزيع أنصبة المعلمين والشعب وفق التخصص والحد الأدنى والمستهدف والأعلى لكل معلم.

**أنصبة موزونة، توزيع أذكى.**

## الوظائف الحالية

- بيانات علوم تجريبية للصفوف 8 إلى 10.
- إضافة وتعديل وحذف المعلمين.
- إضافة متطلبات الصفوف والمواد وعدد الشعب والحصص.
- محرك حتمي يولد ثلاثة سيناريوهات: متوازن، تخصصي، قليل التشعب.
- كشف العجز والتجاوز والشعب غير المسندة.
- حفظ البيانات محليًا داخل المتصفح.
- تصدير CSV وطباعة النتيجة إلى PDF.
- مراجعة اختيارية عبر Gemini من خلال Supabase Edge Function، دون كشف مفتاح API في الواجهة.

## الرفع إلى GitHub

1. أنشئ مستودعًا جديدًا فارغًا في GitHub باسم `qistas`.
2. ارفع جميع محتويات هذه الحزمة إلى جذر المستودع، وليس المجلد الخارجي نفسه.
3. اجعل الفرع الرئيسي باسم `main`.
4. افتح `Settings > Pages`.
5. في `Build and deployment` اختر `Source: GitHub Actions`.
6. افتح تبويب `Actions` وانتظر نجاح workflow باسم `Test and deploy GitHub Pages`.
7. سيظهر رابط التطبيق في خطوة النشر وفي صفحة `Settings > Pages`.

كل push جديد إلى فرع `main` يشغّل الاختبارات ويبني الموقع وينشره تلقائيًا.

## الفحص محليًا عند الحاجة

```bash
npm test
npm run build
```

## ربط Gemini

1. أنشئ مشروعًا في Supabase.
2. أضف السر `GEMINI_API_KEY` في إعدادات Edge Functions.
3. يمكن إضافة `GEMINI_MODEL`، والقيمة الافتراضية في الوظيفة هي `gemini-3.6-flash`.
4. انشر الوظيفة الموجودة في `supabase/functions/review-distribution`.
5. داخل التطبيق أدخل رابط Supabase ومفتاح `anon` في إعدادات مراجعة Gemini.

> لا تضع مفتاح Gemini داخل كود الواجهة أو داخل GitHub Pages. صفحات GitHub عامة، والبشر لديهم موهبة تاريخية في نشر الأسرار ثم الاستغراب من الفاتورة.
