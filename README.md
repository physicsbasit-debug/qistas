# قِسطاس

تطبيق عربي RTL خفيف واحترافي لتوزيع أنصبة المعلمين والشعب وفق التخصص، نطاق التدريس، والحد الأدنى والمستهدف والأعلى لكل معلم.

**أنصبة موزونة، توزيع أذكى.**

## الإصدار 0.2.0: التحكم المرن

أضيفت قوالب سهلة للتحكم في توزيع كل معلم:

- التوزيع المعتاد: تخصصه أولًا والمواد الإضافية عند الحاجة.
- تخصصه فقط.
- تخصصه في صف واحد فقط.
- صف ومادة محددان فقط، مثل علوم الصف الثامن.
- تخصصه مع صف ومادة إضافيين.
- توزيع مخصص بثلاث حالات: مفضّل، مسموح، ممنوع.
- تطبيق نطاق معلم على بقية المعلمين من التخصص نفسه بنقرة واحدة.

جميع حالات «ممنوع» قيود صارمة لا يتجاوزها محرك التوزيع.

## الوظائف الحالية

- بيانات علوم تجريبية للصفوف 8 إلى 10.
- إضافة وتعديل وحذف المعلمين.
- إضافة متطلبات الصفوف والمواد وعدد الشعب والحصص.
- محرك حتمي يولد ثلاثة سيناريوهات: متوازن، تخصصي، قليل التشعب.
- احترام الحد الأعلى ونطاق تدريس كل معلم.
- كشف العجز والنقص والشعب غير المسندة.
- حفظ البيانات محليًا داخل المتصفح مع ترحيل بيانات الإصدار السابق.
- تصدير CSV وطباعة النتيجة إلى PDF.
- مراجعة اختيارية عبر Gemini من خلال Supabase Edge Function، دون كشف مفتاح API في الواجهة.

## الرفع إلى GitHub

1. ارفع الملفات المعدلة إلى جذر مستودع `qistas` مع الحفاظ على المسارات.
2. كل push إلى فرع `main` يشغّل الاختبارات ويبني الموقع وينشره تلقائيًا.
3. افتح تبويب `Actions` وانتظر نجاح `Test and deploy GitHub Pages`.
4. حدّث صفحة التطبيق تحديثًا قويًا عبر `Ctrl + F5`.

## الفحص محليًا عند الحاجة

```bash
npm test
npm run build
```

## ربط Gemini

1. أنشئ مشروعًا في Supabase.
2. أضف السر `GEMINI_API_KEY` في إعدادات Edge Functions.
3. أضف `GEMINI_MODEL` عند الحاجة.
4. انشر الوظيفة الموجودة في `supabase/functions/review-distribution`.
5. داخل التطبيق أدخل رابط Supabase ومفتاح `anon` في إعدادات مراجعة Gemini.

> لا تضع مفتاح Gemini داخل كود الواجهة أو GitHub Pages. المستودع العام لا يعرف معنى الخصوصية مهما كانت نواياه نبيلة.
